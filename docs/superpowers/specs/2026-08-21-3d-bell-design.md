# 仿真手持铃铛设计

## 目标与范围

把现有 iPhone 应用升级为一只可由真实手机姿态和摇动驱动的仿真手持铜铃。用户竖屏握持手机、屏幕朝外时，画面中的铃身保持已确认的正面展示；铃舌则像真实悬挂摆锤一样受三轴重力、平移惯性和旋转惯性共同影响，可在铃腔内全向摆动、贴壁、脱离并再次撞击。手机完全倒置时，铃舌也应自然落向铃腔侧壁，并仍可通过摇动产生新的有效撞击。

视觉目标唯一以用户提供的 `DQ2iOhOnP-...Nk.jpg` 为造型参考。目标不是厚重的大钟，而是一只轻巧、修长、薄壁的小铜手铃：铃身肩部圆润，腰线缓慢外扩，铃口只有克制的薄边外翻；深棕色细长木柄通过短银色连接环与铃身相连；空腔内壁和铃舌从正面略低视角清楚可见。当前已通过真机确认的模型比例、相机、灯光和页面布局全部锁定，本功能不得重新调整。

声音开关默认关闭。声音关闭时，运动采样、铃舌动画、真实碰撞计数和触觉反馈仍然运行。完整功能分两阶段实施：第一阶段完成三维重力铃舌和真实碰撞；第二阶段完成由同一碰撞事件驱动的实时模态金属声音。

## 已确认的使用姿态

- 应用锁定竖屏，手机自身就是现实中的“铃铛把手与铃身”。
- 用户通常竖直握持、屏幕朝外并左右摇动，但功能不能只处理屏幕横轴。
- 手机可缓慢向任意方向倾斜、平放或上下倒置；铃舌应持续跟随世界重力改变悬垂方向。
- 完全倒置时，铃舌停靠在哪一侧由倒置过程中的连续运动决定，不允许随机跳边。
- 冷启动时若手机恰好完全倒置，在没有足够方向信息前保持稳定；第一次可辨识的小幅运动决定停靠侧。
- 倒置后仍可摇铃。静态贴壁压力不是新碰撞，动态法向冲击达到阈值时才允许再次触发。
- 画面中的铃铛保持正面展示，不根据设备姿态变成可浏览的 3D 全景。
- 手动拖动只作为小幅度外观检查，不能缩放、平移或绕铃铛完整旋转。

## 技术选择

继续使用 SceneKit + SwiftUI `UIViewRepresentable`。铃身、手柄、连接环和铃舌保持独立节点；SceneKit 只负责显示，不负责判断碰撞或触发声音。

新增纯 Swift 三维铃舌模拟器，保存铃舌单位方向向量和切平面角速度，并在铃铛局部坐标系内进行固定时间步长积分。渲染层使用四元数把铃舌杆从静止轴对齐到模拟方向，避免使用欧拉角造成万向节锁和跨方向跳变。

外部 USDZ/SceneKit 模型保留为后续替换选项，但在没有核实授权、空腔结构、独立铃舌节点和移动端性能前，不把第三方资源作为当前版本依赖。

## 已锁定的几何与材质

- 铃身：使用平滑曲线采样后的二维截面绕竖直轴旋转，外轮廓至少 48 个高度采样；肩部饱满但不笨重，腰线修长，最大半径只在最下方薄铃口出现。
- 铃口：由外壁、圆滑边缘和内壁连续形成，边缘薄而略向外挑，不采用厚圆环，不形成大钟式喇叭口。
- 网格：径向至少 192 段；显式生成连续法线，外壁、内壁和铃口分别采用正确朝向，禁止出现竖向切面、三角面色带和闭合接缝。
- 手柄：独立的深棕木质旋转体，细长、轻微不对称视觉曲线，上端尖圆，下端收窄接入银环；不能使用黄铜材质。
- 连接环：短而窄的银色金属节点，尺寸明显小于铃身肩部。
- 铃舌：中心细杆和球形舌头，位于空腔内部，正面低角度镜头可见。转轴高度为 `0.56`，球心距转轴 `0.82`，球体半径 `0.072`；静止时球体下缘与铃口底沿基本对齐。
- 材质：铃身使用低饱和暖金色黄铜，金属度接近 1、中高粗糙度，并以很弱的环向拉丝纹理打散高光；禁止纯黄、纯橙和大片白色过曝高光。内壁比外壁略暗。
- 灯光：使用大面积柔和主光、弱补光和环境光形成参考图中的宽柔高光；不使用高强度橙色点光源。
- 镜头：固定的正面略低、轻微三分之四视角，完整显示木柄并留出顶部安全距离，让铃口内壁和铃舌可见；不允许用户通过相机控制查看背面全景。
- 场景：接近纯白背景，不放地板，不显示倒影或地平线。
- 比例：铃身相对木柄在宽、高、深三个方向缩小 20%，整只铃铛再通过相机距离缩小 10%；该比例已通过真机截图确认。
- 展示姿态：静止模型向镜头固定倾斜约 15.5°，确保椭圆铃口、内壁和铃舌同时可见；该基础姿态只用于画面构图，不参与重力计算。
- 色彩管理：关闭相机 HDR 和负曝光，SceneKit 场景与 `SCNView` 使用不透明纯白背景。

## 第一阶段：三维重力铃舌

### 数据流与职责

CoreMotion 以 100Hz 采样。`MotionService` 只负责获取三轴重力、三轴用户加速度、三轴旋转速度和时间戳；`BellViewModel` 将其转换成完整的 `BellMotionInput`，管理模拟器并发布渲染状态和碰撞事件。SceneKit 视图不得直接访问 CoreMotion。

```text
MotionSample
    → BellMotionInput（三轴重力、用户加速度、旋转速度、时间戳）
    → BellClapperSimulator.step(input:)
    ├─ BellClapperState（方向、切向速度）→ BellSceneView
    ├─ BellContactState（贴壁、法向加速度、切向速度、接触方向）→ 持续接触声音
    └─ BellImpactEvent → 计数 / 触觉 / 撞击声音
```

`BellPhysicsEngine` 不再根据加速度幅值、jerk 或方向反转猜测碰撞。计数、触觉和声音只能由 `BellClapperSimulator` 产生的真实接触事件驱动。

### 三维摆锤状态

模拟器至少保存：

- 从铃舌转轴指向球心的单位方向向量；
- 位于该方向切平面内的角速度；
- 上一次稳定重力方向；
- 当前是否接触内壁及接触法向；
- 上一次有效撞击时间和强度；
- 倒置临界状态下继承的停靠侧。

每个采样步执行：

1. 将设备重力转换到铃铛局部坐标系；展示用的 15.5° 固定倾角不能污染物理坐标。
2. 将用户平移加速度与旋转产生的惯性项加入有效重力。
3. 把有效重力投影到摆锤切平面，结合阻尼积分铃舌方向和切向角速度。
4. 归一化方向向量并限制异常时间步，避免数值漂移和传感器毛刺。
5. 检查铃舌是否到达铃腔边界；若发生新撞击，生成一次 `BellImpactEvent`。

### 与铃腔几何一致的碰撞边界

铃舌活动空间以半角 `0.36` 弧度（约 `20.6°`）作为硬上限，但不能把它当作所有方位完全相同的固定圆锥。碰撞边界必须同时计入铃球半径 `0.072`、枢轴的前向偏移 `0.030`、球心高度以及对应高度的铃腔内壁半径，并保留 `0.008` 的视觉安全余量。由于枢轴不在铃身轴线上，朝镜头方向的安全摆角会略小，左右和向后方向可在空间允许时保留原最大摆幅。

到达边界时：

- 把越界位置投影回圆锥表面；
- 仅反转并衰减法向速度，初始恢复系数沿用 `0.24`；
- 保留切向速度，使铃舌可沿内壁滑动，而不是被锁死在二维平面；
- 静态贴壁压力不产生重复事件；
- 接触期间出现新的足够大法向冲量时，可再次产生撞击；
- 强烈反向摇动可使铃舌脱离当前侧并撞向另一侧。

旋转惯性项按物理量级 `1.0` 参与计算，不再使用早期演示参数 `0.18`。正向腕部角加速度应使铃舌在设备局部坐标中向反方向滞后，并在输入停止后保留连续角动量；不得让铃舌视觉上跟随手机同向摆动。

### 姿态行为

- 竖直正放：铃舌趋向铃腔中心并自然衰减到静止。
- 任意方向倾斜：铃舌沿三维最短路径向新的重力悬垂方向移动。
- 手机平放：铃舌趋向前侧或后侧内壁，允许因遮挡只显示部分铃舌。
- 完全倒置：铃舌落到圆锥边界并停靠；停靠侧继承倒置前的连续运动，不随机切换。
- 倒置摇动：新产生的动态法向冲击可触发撞击；持续静压不重复触发。

### 统一碰撞事件

第一阶段建立稳定的 `BellImpactEvent`，至少包含：

- `timestamp`：碰撞时间；
- `strength`：归一化撞击力度；
- `normalSpeed` 或等价法向冲量；
- `contactDirection`：铃铛局部坐标中的撞击方向；
- `contactPoint`：可由方向与铃腔几何推导的接触位置；
- `tangentialSpeed`：沿内壁方向的相对速度。

事件加入短冷却窗口，只用于抑制同一次接触在连续帧中重复触发；冷却不能吞掉脱离后重新撞击，也不能禁止倒置贴壁时出现的新动态冲击。

### 持续接触状态

`BellImpactEvent` 继续代表离散撞击，不得被改造成高频重复事件来伪造摩擦。`BellSimulationStep` 另外输出最新 `BellContactState`：

- `timestamp`：状态采样时间；
- `isTouchingWall`：铃舌是否与内壁接触；
- `normalAcceleration`：试图把铃舌继续推向边界外侧的有效线加速度，单位为 `m/s²`；声音层再通过集中配置映射为归一化载荷，不使用静态布尔值代替；
- `tangentialSpeed`：接触点沿内壁滑动的相对速度；
- `contactDirection`：铃铛局部坐标中的接触方向。

状态在每个有效物理采样步更新。脱离内壁、输入无效、模拟器重置、声音关闭或应用进入后台时，必须发送或恢复为明确的非接触状态，不能让音频端保留卡住的摩擦声。持续接触状态只驱动声音，不增加碰撞计数，也不触发触觉。

## 第二阶段：实时模态金属声音

### 声音目标与边界

第二阶段实现移动端实时模态合成，而不是在手机上实时求解铜壳有限元和周围空气声场。目标是得到具有非谐波频率、自然衰减、撞击位置差异和多次余音叠加的可信小铜铃声音。

若要求与某一只实体铃铛的音色完全一致，必须提供该实物的高质量单次撞击录音或经过测量的模态频率、衰减时间和权重；没有这些数据时只能实现物理合理、听感逼真的目标音色，不能宣称一比一复刻特定实物。

### `BellModalAudioEngine`

声音引擎只消费第一阶段输出的 `BellImpactEvent` 和 `BellContactState`，不重新读取传感器，也不自行猜测接触或碰撞。

- 使用约 12–30 个非谐波阻尼模态并行合成铜铃主体余音。
- 每个模态具有独立频率、衰减时间、增益和轻微非线性响应；`decay` 采用 T60 语义，即指定时间后振幅约衰减至 `0.001`（−60 dB）。
- `strength` 控制总能量、明亮度和被激发的高频模态数量。
- `contactDirection` 与 `contactPoint` 改变各模态权重，使不同撞击侧听起来不完全相同。
- 撞击路径继续由 `BellImpactEvent` 激发主体模态；撞击中的切向速度只允许轻微改变起音明亮度，不能直接混入白噪声。
- 多次撞击允许余音重叠，不截断前一次衰减；并限制总能量，防止连续摇动削波。
- 声音开关默认关闭。关闭时不启动或保持活跃的实时合成渲染，但物理、计数和触觉继续运行。
- 实时引擎初始化或恢复失败时，回退到现有铃声样本；回退不能影响物理模拟。

### 铃舌—铜壁滑动接触声

持续接触声属于金属—金属滑动刮擦声与表面微碰撞声的混合体，采用“接触激励源 + 铜铃模态共振”实现，而不是把原始随机噪声直接混入最终输出。

1. DSP 维护预分配、固定种子的多尺度表面粗糙度轮廓；接触相位按 `tangentialSpeed` 连续推进，不能在每个 100Hz 状态包到达时重新随机或重置。
2. 粗糙度轮廓产生不规则微冲击和低能量摩擦激励。由 `normalAcceleration` 映射出的载荷控制总体能量，`tangentialSpeed` 控制微冲击密度与频谱明亮度；任一值趋近零时，接触激励自然趋近静音。映射阈值集中存放在接触声配置中，不散落到物理、视图或 DSP 调用处。
3. 接触激励主要注入铜铃的中高频模态，最终听到的颗粒必须带有现有小铜铃的材质共振。禁止把干燥白噪声、粉红噪声或未经过铃体共振的擦声直接加到输出。
4. 接触开始使用 `5–10ms` 平滑包络，结束使用 `30–50ms` 平滑包络，避免点击声；状态短暂丢包时沿最近速度平滑外推，超过 `80ms` 未收到有效接触更新后必须自动释放到静音，防止卡住。
5. 缓慢转圈产生轻微、稀疏、偏暗且可能间断的铜质微碰撞；速度增加时颗粒更密、更明亮，但不简单变成更响的连续“沙沙”声。
6. 离散撞击与持续接触共享同一组铃体模态并允许余音叠加，但保持独立激励路径。正式撞击始终是主体，接触声只提供贴壁滑动细节。
7. 样本回退只保证离散撞击可用，不伪造持续接触声；模态引擎不可用时持续接触层保持静音。

持续状态通过有界、无阻塞通道进入 DSP。若音频消费暂时落后，可丢弃过时中间状态并收敛到最新状态；非接触状态和超时释放必须保证最终静音。

### 音频稳定性

- 模态源节点与样本回退内部统一使用非交错 Float32、48 kHz、双声道格式；样本必须在连接和调度前完成转换，避免再次出现 `channelCount` 不一致导致的异常退出。
- 实时渲染回调中禁止内存分配、锁、文件读取、日志和主线程 UI 操作。
- 预分配模态状态、声音实例和工作缓冲区；碰撞事件通过无阻塞的有界队列传入。
- 表面粗糙度数据、接触包络和微碰撞状态必须在 DSP 创建时预分配；音频线程中不得生成容器、随机分配或调用 Swift。
- 处理耳机插拔、蓝牙线路变化、系统音频中断、媒体服务重置和引擎配置变化；恢复失败时保持静音或进入样本回退，不影响系统其他音频。
- 音频会话不得长期压制用户正在播放的音乐。声音关闭或页面退出时应释放不再需要的音频会话占用。

## 页面与交互

- 3D 铃铛占据页面中上部，底部保留加速度、碰撞、力度和调试入口。
- 声音 Toggle 默认关闭，放在主界面可见区域。
- `allowsCameraControl` 保持关闭。
- 仅保留受限 `UIPanGestureRecognizer`，水平和垂直角度均有明确上限；不添加 pinch、平移和相机缩放。
- 真机运动是主要交互；手动拖动只用于检查模型外观，不参与铃舌物理输入。

## 异常处理与性能

- 重力值无效或短暂缺失时保持最后一个稳定方向并逐步衰减速度，不产生虚假碰撞。
- CoreMotion 不可用时显示静止铃铛，计数不增加，不伪造传感器数据。
- 时间戳倒退、过大时间间隔或单次传感器尖峰必须被限幅或丢弃。
- 物理采样目标为 100Hz，画面渲染目标为 60Hz；渲染只读取最新稳定状态，不反向影响模拟。
- 应用进入后台时停止采样和实时渲染；恢复后重新建立基准，不能把后台时间差积分成一次巨大撞击。
- 声音关闭时，动效、计数和触觉行为必须与声音开启时一致。

## 验收标准

### 自动化验证

1. 竖直静止时铃舌回到中心，速度衰减且不产生碰撞。
2. 向左、右、前、后及组合方向倾斜时，铃舌方向连续跟随对应重力方向。
3. 完整绕转过程中方向连续，无欧拉角跳变或万向节锁。
4. 任意输入下铃舌角度不超过 `0.36` 弧度，并满足当前方位的几何安全角；完整球体与内壁至少保留规定的视觉安全余量。
5. 完全倒置静止时铃舌稳定停靠在边界，连续帧不重复计数。
6. 完全倒置后施加足够摇动，能够产生新的有效碰撞。
7. 持续贴壁本身不生成新的 `BellImpactEvent`；只有出现新的合格法向冲量才生成一次离散撞击事件。
8. 无效重力、异常时间戳和传感器尖峰不会产生 NaN、跳边或虚假碰撞。
9. `BellImpactEvent` 的力度、方向、位置和切向速度均在约定范围内，事件冷却不会吞掉真实二次撞击。
10. 模态声音离线渲染无 NaN、无削波，频谱主峰和衰减包络落在预设容差内。
11. 单声道和立体声输出线路均能建立兼容格式，不出现声道数不匹配。
12. 非接触、零法向加速度或零切向速度不产生新的持续接触能量；结束接触后擦碰层在限定时间内平滑释放到静音。
13. 相同载荷下，缓慢滑动的微碰撞密度和高频能量低于快速滑动；两者输出均有限、连续且不含状态包边界点击声。
14. 接触激励的主要输出能量经过既有模态共振，关闭模态注入时不会残留独立的干燥噪声通道。
15. 持续接触更新不会增加碰撞计数或触发触觉；真实强撞击仍产生一次统一事件和清晰金属起音。

### 真机验收

1. 声音开关默认关闭，打开前不抢占或中断用户音乐。
2. 手机竖直静止时铃舌自然悬垂；缓慢向四周倾斜时连续跟随，不抖动、不瞬移。
3. 手机屏幕朝上和朝下平放时，铃舌方向与现实重力一致。
4. 缓慢完整倒置时，铃舌平滑滑向并停靠内壁，不随机跳到另一侧。
5. 正向和倒置状态都能通过摇动产生可见、可计数的真实撞击。
6. 静态贴壁不连续响；脱离重撞或新的动态冲击可以再次响。
7. 铃舌与铃身碰撞在画面、触觉、计数和声音上时间一致。
8. 模态铃声具有清晰金属起音、非谐波余音和自然衰减；不同力度和撞击方向可听出变化，连续摇动允许余音叠加但不失真。
9. 慢速、中速和快速转圈摇动时，擦碰声分别呈现由稀疏偏暗到密集明亮的连续变化，均带铜铃共振，不出现电子噪点、纸张沙沙声或状态更新造成的突兀接缝。
10. 铃舌贴壁但相对滑动接近停止时，擦碰声自然减弱；离壁后及时消失；直接左右摇铃的撞击力度和主体音色不因接触层而明显变弱。
11. 耳机插拔、蓝牙切换、系统中断和返回前台后，应用不异常退出，也不导致系统音乐长期无声。
12. 已确认的铃铛比例、正面视角、材质、灯光和页面布局不发生改变。
13. iPhoneOS 构建通过；最终运动手感和声音听感以真机验收为准。

## 实施顺序

1. 先完成第一阶段：设备方向锁定、完整运动输入、纯 Swift 三维模拟、锥形碰撞、统一碰撞事件和 SceneKit 四元数渲染。
2. 第一阶段通过自动化测试和真机姿态矩阵验收后，再接入第二阶段实时模态声音。
3. 第二阶段先以可调模态参数完成安全稳定的声音引擎，再根据真机听感或目标铃录音调音。
4. 两阶段共用 `BellImpactEvent` 和 `BellContactState`，禁止第二阶段复制独立的碰撞或接触判断。

## 不包含

- 在 iPhone 上实时进行有限元铜壳与空气传播求解。
- 在没有目标实物录音或测量数据时宣称声音与某一只实体铃铛完全相同。
- 自动下载或使用未经授权的第三方模型与声音资源。
- 根据手机姿态把相机旋转成可浏览的 3D 全景。
- 修改已经由用户确认的铃铛视觉比例、材质、相机和页面布局。
